# FN26 implementation plan

> Execute inline with executing-plans; retain all existing user changes. No commit, push or FE changes.

Goal: generate and persist a seven-day maintenance-calorie vegetarian menu, one dish per breakfast/lunch/dinner.
Architecture: authenticated controller -> MealPlanningService -> MealPlanningRepository. Pure bounded algorithm uses diet/allergy filtering, suitable times, no duplicate dishes and reasonable portions. No AI calls.
Spec: the accepted FN26 design in this conversation (maintenance, not autonomous weight-loss treatment).

Constraints: reuse DTOs, shared pagination, AutoMapper, FluentValidation and PostgreSQL patterns. No SQL Server snapshot changes. Known allergy families expand across ingredients; unknown custom aliases block generation rather than silently bypass filtering. Adult generation requires age >=20 and valid energy inputs. Snapshot target/quantities/names; do not mutate BMI history while generating. New nullable jsonb generation_snapshot preserves existing templates.

Tasks:
- [x] Unit probes: calorie targets/portion math, full coverage and uniqueness, vegan/egg-dairy, allergy variants/unknown aliases, insufficient catalog and invalid profiles.
- [x] DAL aggregate loading + atomic plan/schedule persistence; owner-scoped read/list.
- [x] BLL DTOs, validation, maintenance estimate reuse, bounded generation and snapshots.
- [x] API generate/list/detail, DI, migration for snapshot.
- [x] PostgreSQL/API probes: guest/ownership, full persistence/read, rejected input no partial writes, migration/RLS compatibility; use isolated local PostgreSQL, never cloud test fixtures.
- [x] Review full diff, document contract, limitations and verification. No outward Git action.

Rulings: no new health goal fields or autonomous calorie deficit. Existing generation_source='manual' means rule-based application generation; distinguish by algorithmVersion='rules-v1'. Existing sample dishes are unreviewed and calories-only; advertise estimates, not nutritional adequacy or guaranteed BMI outcome. Retain exact source snapshot for each generated menu. No change to existing BMI endpoint categorization in this scope.

Outcome: 217 unit and 43 isolated PostgreSQL/API tests passed. Nullable generation_snapshot migration previewed then applied on shared Supabase, without writing generated user plans. Reviewer confirmed unresolved-alias bypass fixes. Calendar uses DayIndex relative to start and ISO DayOfWeek for schedules/reminders. Protected excluded SQL Server snapshot retained its original SHA-256. No commit/push or FE changes.
